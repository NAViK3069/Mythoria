# 0009 — ข้อมูลเกมชุดแรกใน packages/game-data: ธาตุและเผ่า

- สถานะ: Accepted
- วันที่: 2026-11-09

## บริบท
- เจ้าของเกมกำหนด 5 ธาตุ (ไฟ → ไม้ → น้ำ → ไฟ, แสง ⇄ มืด) และ 10 เผ่า; ฮีโร่ระดับสูงมีหลายธาตุได้แต่รับดาเมจตามธาตุแรก (แบบ Dragon City)
- กติกาโปรเจกต์: ตัวเลข/ข้อมูลเกมต้องอยู่ใน `packages/game-data` ไม่ใช่ในโค้ด client — แต่แพ็กเกจยังมีแค่ README
- ต้องการไอคอนธาตุ/เผ่า และตัวกรองในหน้าฮีโร่ ก่อนเริ่มระบบฮีโร่

## การตัดสินใจ
- **`packages/game-data` เป็น npm workspace package** (`@mythoria/game-data`) ไฟล์ TS ล้วน ไม่ต้อง build — `exports` ชี้ `src/index.ts` ตรงๆ, client ใส่เป็น dependency `*`; Vite และ `tsc` (moduleResolution bundler) อ่านได้เลย
  - `elements.ts`: รายการธาตุ (ชื่อไทย สี), `BEATS`, `matchup(attack, defender)` → strong/normal/weak โดยดูธาตุแรกของฝ่ายรับเท่านั้น, `MATCHUP_DAMAGE` (ตัวแทน = 1 รอเจ้าของเกม)
  - `races.ts`: 10 เผ่า (ชื่ออังกฤษ + ไทยตามที่เจ้าของเกมตั้ง)
  - ระบบต่อสู้ (`packages/combat`) จะใช้ชุดเดียวกันนี้
- **ไอคอน**: PixelLab 1 งาน 64 แบบ (15 ไอคอน × 4) ใช้ไอคอน UI เดิมเป็นภาพอ้างอิงสไตล์ → เลือก: ธาตุเป็นเหรียญกลมขอบทองชุดเดียวกัน, เผ่าเป็นตราประจำเผ่า (`tools/build_ui_assets.py` → `el_<id>.png`, `race_<id>.png`)
- **หน้าฮีโร่**: เปลี่ยนแท็บบทบาท (แทงก์/โจมตี/สนับสนุน — ไม่ใช่สิ่งที่เจ้าของเกมกำหนด) เป็นตัวกรองธาตุ + เผ่า (+ "เฉพาะธาตุแรก"); `player.heroes: OwnedHero[]` (ว่างไว้จนมีระบบฮีโร่)

## ผลที่ตามมา
- ข้อมูลเกมชุดต่อไป (ฮีโร่ สกิล ศัตรู) ใส่ใน `packages/game-data` แบบเดียวกัน
- ทดสอบตัวกรองด้วยฮีโร่ทดสอบชั่วคราว (ไม่บันทึก): ธาตุ/ธาตุแรก/เผ่า/ล้าง ได้ผลถูกต้อง

## ภายหลัง (2026-11-10)
- เจ้าของเกมกำหนดว่า **ฮีโร่หนึ่งตัวมีธาตุเดียว** เรื่องหลายธาตุ/ธาตุแรกด้านบนจึงเลิกใช้
  - `HeroDef.elements` เปลี่ยนเป็น `element`
  - `matchup(attack, defender)` รับธาตุเดียว
- ตัวกรอง "เฉพาะธาตุแรก" ในหน้าฮีโร่เอาออกแล้ว
- ตัวกรองทั้งหมดพับเหลือแถบเดียว ดูรายละเอียดใน ADR 0004
